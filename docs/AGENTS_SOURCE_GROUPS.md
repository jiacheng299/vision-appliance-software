# 智能体、通道监测组与多视频源

更新：2026-10-22，按用户最新确认的业务结构落地。本说明覆盖旧文档中“一通道只能绑定一个视频源”的限制。

## 层级

智能体代表一种业务，例如火灾探测。智能体包含多个通道；每个通道是一个业务监测组，共用需求、目标、规则、时长、模型/模板引用。通道内可绑定多个视频源，包括直播和录像；每个源单独保存ROI和录像范围。

同组视频分别分析、分别记录报警；这不是跨镜头融合或跨摄像头身份跟踪。通道统一启动/停止/应用；底层每个源建立独立Run，保留channel_id与source_id。单个源失败如实显示部分结果，不伪造整组成功，不影响其他通道。

## 怎样操作

1. 视频源管理中先导入录像或登记摄像头。
2. 新建智能体草稿时，在“首个通道的视频源”多选，自动生成一个监测组；也可先保存空草稿。
3. 在监测配置编辑器中添加更多通道。每个通道上方多选组内视频，下方设置共享需求、模型和规则。
4. 每个视频独立设置区域和录像区间。区域不能直接共用不同镜头的像素位置；新增视频默认没有ROI，需要单独绘制。
5. 验证会检查每个视频的必要条件；任何必需条件缺失都会阻止该配置发布。
6. 发布后选择通道组启动/应用，确认框列出组内所有受影响旧Run。
7. 在“画面与报警”切换“监控墙”：默认多视频时展示墙，按通道分组。每页1/4/9画面，点击单画面或“打开本页画面”加载；“关闭本页画面”、翻页、切换视图会释放相应播放器。墙可全屏。
8. “停止整个通道”处理组内所有活动视频，其他通道继续。各视频分别显示实际版本、状态与报警来源。

预览不等于分析。未运行视频只调用源预览；摄像头网关未接入时如实提示。演示画面有模拟标识；真实推理、事件和媒体仍需公共提供方。

## API与兼容

ChannelConfig新增sources[]，元素包含source_id、regions、start_media_ms、end_media_ms；共享规则留在ChannelConfig根部。旧source_id/regions/range字段只用于兼容老版本，不能同时与新sources混填。

每通道最多16个不同源，一个智能体最多16通道、合计64条源绑定。这是配置上限，不是硬件并发性能承诺。同一个源可用于不同通道，组内不能重复。

sources为空时序列化省略该字段，旧快照和hash保持原状；读旧库时按单源组解释，不重写历史。无需新建数据库迁移。

新增POST /api/v1/agents/{agent_id}/channels/{channel_id}/stop，返回可查询Operation；旧单Run停止接口保留兼容，当前界面使用通道组停止。ChannelOperation新增source_id，每个源分别反馈结果。

公共提供方需显式supports_grouped_sources=True才可验证或启动新sources配置，防止旧执行器只处理第一个源。必须按(channel_id,source_id)管理Run唯一性、按通道锁定组操作、校验完整expected_active_run_ids，并返回删除源的停旧结果及每个新源的结果。源引用查询、源快照、事件关联、列表筛选、播放ROI、复测和实际版本汇总均覆盖组内所有源。

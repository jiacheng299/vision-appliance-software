## 使用与实现边界

- 先运行 `start-camera-lab.cmd`，再在主项目中使用网关发布的 RTSP 地址；完整步骤见 [摄像头资源说明](CAMERA_LAB.md)。
- 当前解码与浏览器预览针对本机 MediaMTX 已发布的视频；不会自动将任意外部 RTSP 地址接入网关。
- “在线”表示最近一次成功解码的采样结果。复检周期为 30 秒，实际完成时间受队列并发与连接超时影响。
- 网关监听回环地址，媒体代理约束资源路径、重定向和响应大小；浏览器不接收摄像头凭据。
- 视频、数据库、运行日志、二进制工具及本机截图位于忽略目录，不随源码提交。

## 2026-10-26：状态刷新不重建播放器

- 问题：快速监控看板收到状态通知或轮询结果后，会替换视频源对象；播放器将返回新数组的监听 getter 当成变化，即使视频源 ID 和自动播放选项未变，也会释放并重新创建视频，导致闪烁和录像从头播放。
- 修复：分别监听视频源 ID 与自动播放选项，仅在这两个值实际变化时重置。保留实时通知、15 秒轮询、状态标签更新、录像循环及切换视频源时的资源清理。
- 回归：新增 HLS 与本地录像两项测试，连续替换同 ID 的状态、名称、检测时间和版本号，确认 video 元素、播放位置与 HLS 实例保持不变，不重复请求播放会话；先复现失败，再修复通过。
- 验证：前端全量 63 项测试通过，TypeScript 检查和生产构建通过；浏览器直播连续播放跨越多个刷新周期，12 秒录像完整循环。

## 2026-10-26：看板逐路重连与重播

- 问题：摄像头失败或断开后，看板不再挂载播放器，播放器内部的重试按钮也消失，用户无法就地重连。
- 修改：在每个画面下方保留摄像头“重新连接”和就绪录像“重新播放”按钮。摄像头复用现有连接检测 API，显示连接中状态并防止重复点击，恢复后自动播放；失败时显示具体错误并保留下一次重试入口。
- 隔离：显式重试仅更新所选画面的播放器实例，其他画面及正常状态刷新不触发重播。未就绪录像不能通过重播按钮绕过探测流程，仍可点击名称进入详情处理。
- 验证：新增失败、断开、录像单路重播、请求失败后再次尝试四项回归；前端全量 67 项测试和生产构建通过。浏览器实测夜间录像摄像头重连后恢复在线，失败的公开摄像头仍可发起检测。

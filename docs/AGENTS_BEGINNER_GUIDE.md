# 智能体管理：从零开始看懂与操作

本轮里程碑：真实草稿管理。更新时间：2026-10-20。

## 1. 先记住四个词

| 名称 | 可以怎样理解 | 例子 |
|---|---|---|
| 智能体 Agent | 一个长期保存的监测任务文件夹 | 北门滞留监测 |
| 通道 Channel | 文件夹中某一路视频及其监测条件 | 北门摄像头，人员停留 30 秒 |
| 配置版本 Revision | 某一版监测设置 | v1 是 30 秒，复制出的 v2 改成 60 秒 |
| 运行 Run | 真正按某个版本执行的一次监测 | 今天 9 点启动的一次分析 |

现在做的是前面三项的草稿管理。Run 所依赖的模型评估和运行服务还没有接入。
**看到“草稿已保存”表示设置存进数据库了，不表示正在识别画面。**

## 2. 现在能做什么

- 新建一个有名称、说明的智能体草稿，在列表中看到它。
- 搜索名称或说明，按视频源筛选，分页加载卡片。
- 编辑名称、说明和多路监测配置。
- 为通道选择已保存的视频源，填写需求、对象、规则和持续时长。
- 对录像填写分析起止位置；有缩略图时用鼠标画多边形区域。
- 保存配置，刷新页面后继续查看。
- 把 v1 复制为独立的 v2，再修改 v2；v1 的内容保持不变。
- 在画面页打开视频源预览。录像能否播放仍取决于媒体是否准备好；摄像头需要后续网关接入。
- 两个窗口同时编辑时，拒绝旧窗口覆盖新数据，并保留输入、提示冲突。

本轮没有实现：模型选择与能力评估、发布确认、真实启停、应用新版本、实时检测框、报警订阅、证据核查、反馈、漏报、复测和导出。
相应区域会明确提示未接入，验证和启动按钮保持禁用。没有编造运行或报警数据。

## 3. 怎样打开

项目根目录就是包含 `start.cmd`、`README.md` 和 `frontend` 文件夹的目录。

### 这台电脑上

本轮已安装前后端依赖并构建页面。正常使用时可以双击根目录的 **start.cmd**，然后在浏览器打开：

```text
http://127.0.0.1:8000/agents
```

如果 8000 端口被占用，在项目根目录打开 PowerShell，执行：

```powershell
.\start.cmd --port 8003
```

然后访问 `http://127.0.0.1:8003/agents`。
运行窗口要保持打开，按 Ctrl+C 或关闭窗口会结束这次服务。
首次使用正常工作数据库时，要自行建立管理员；正式使用没有预置账号。

本轮浏览器验收使用了单独的 `.artifacts/agent-preview` 数据库和本机 8002 端口。
该环境的样例是开发测试数据，不是现场监测结果，也不与正常 `var/` 数据库混用。
8002 预览服务停止后，可以用下面的命令重新打开它（只用于本地学习）：

```powershell
$env:VISION_VAR_ROOT = "$PWD\.artifacts\agent-preview"
.\.venv\Scripts\python.exe -m uvicorn app.main:create_app --factory --app-dir backend --host 127.0.0.1 --port 8002
```

若要恢复普通工作数据库，关闭预览进程，在新终端运行 `start.cmd`，或先删除当前终端的 `VISION_VAR_ROOT` 环境变量。

### 换一台电脑

按根目录 README 安装 Python 3.13 和 Node.js 22.12+ 或 24 LTS，再执行 `setup.cmd`。
本机验证使用 Python 3.12.14 和 Node.js 24.19.0，原始依赖锁定文件未改动。
开发机器安装不等于客户现场的完整离线安装包验收。

## 4. 第一次照着做

1. 登录后点击左侧“智能体管理”。
2. 点击“新建草稿”，输入“北门人员滞留监测”，再点击“创建草稿”。
3. 进入“监测配置”，点击“编辑草稿”。
4. 点击“添加一路监测”，把通道名称改成“北门”。
5. 填写“有人在北门指定区域停留超过 30 秒时报警”。
6. 在持续时长中填写 30。视频源还没准备好时可以先不选，先保存草稿。
7. 点击“保存草稿”。刷新页面，确认刚填写的内容仍然存在。
8. 点击“复制为新版本”，看到 v2，再编辑 v2，把 30 改成 60 并保存。
9. 在上方版本选择器中选择 v1，确认仍然是 30 秒；选择 v2，确认是 60 秒。
10. 打开“版本与运行历史”，应看到两个配置版本，但运行记录仍为空。

这条操作验证了最基本的开发闭环：**填写 → 保存 → 重新读取 → 复制版本 → 保留旧版本**。

## 5. 视频源与绘制区域

先到“视频源管理”导入自己的测试录像，等待探测和转码成功；这一步需要媒体工具和 Worker。
再回到智能体编辑页选择录像。有缩略图后，可以点击画面上的多个点，最后点“保存区域”。
区域至少三个点，边界不能相互交叉。点错可以“撤销点”，已经保存的区域可以移除。
画完后还需点击编辑抽屉底部的“保存草稿”，才会写入数据库。

录像起止位置在界面中按“秒”填写，后端存成毫秒，以便准确定位。
开始必须早于结束，结束不能超过录像时长；两项都不填写表示暂未指定片段。
更换视频源会清空旧区域和录像区间，因为原来在北门画的区域不应直接套在另一个画面上。

画面页是视频源预览，不是本次分析进度，也没有真实检测框。后续接入运行服务后还要区分播放位置和分析位置。

## 6. 这些提示是什么意思

| 提示 | 意思及处理 |
|---|---|
| 模型评估与运行服务尚未接入 | 相关公共模块还没接上；先保存草稿，不能启动 |
| 视频源不存在或已归档 | 原视频已不可用于新配置；回视频源管理检查或重新选择 |
| 配置已被其他页面更新 | 另一个窗口先保存了；先复制自己要保留的文字，再取消、刷新、重新编辑 |
| 信息不符合要求 | 检查区域是否交叉、录像区间、名称和时长；失败不会覆盖已保存的数据 |
| 无法连接本机服务 | 确认运行窗口还开着、网址端口正确，再重试原操作 |

同一次创建请求如果超时，保持名称和说明不变，再点“创建草稿”，会使用同一个请求编号。
后端会返回原结果，避免多建一张卡片。修改内容或关闭后重新打开创建窗口，表示一次新创建。

## 7. 代码放在哪里

| 路径（相对项目根目录） | 用初学者的语言解释 |
|---|---|
| `frontend/src/modules/agents/AgentsPage.vue` | 卡片列表和新建窗口 |
| `frontend/src/modules/agents/AgentDetailPage.vue` | 画面、配置、版本等详情页 |
| `frontend/src/modules/agents/RevisionEditor.vue` | 右侧弹出的配置编辑表单 |
| `frontend/src/modules/agents/RegionEditor.vue` | 在缩略图上画区域 |
| `frontend/src/modules/agents/api.ts` | 网页向后端发请求的入口 |
| `backend/app/modules/agents/routes.py` | 后端接收请求的“窗口” |
| `backend/app/modules/agents/service.py` | 创建、保存、复制、冲突检查等业务处理 |
| `backend/app/modules/agents/models.py` | 数据库中智能体、版本和请求记录的结构 |
| `backend/app/modules/agents/schemas.py` | 接口允许哪些字段，以及数据格式规则 |
| `backend/alembic/versions/0002_agents.py` | 在旧数据库上增加新表的升级脚本 |
| `contracts/openapi.json` | 给 A、B 和前后端共用的接口说明 |
| `frontend/src/shared/api/generated.ts` | 从接口说明自动生成的类型，避免双方字段写错 |
| `tests/backend/test_agents.py` | 自动检查保存、版本、权限和并发是否正确 |
| `frontend/tests/agents.test.ts` | 检查表单失败后是否保留输入、切源是否清空旧区域等 |

“前端”是浏览器里的画面；“后端”负责接收操作、检查规则并保存数据；“数据库”负责关掉页面后仍记住设置。
点击保存时，大致经过：表单 → api.ts → routes.py → service.py → SQLite。

## 8. 接下来怎么开发

1. 和 A、负责人一起评审 `docs/AGENTS_API.md`，确认多通道结构和接口。
2. A 接入模型与模板目录，提供真实能力字段及校验接口；B 不复制模型管理规则。
3. 公共分析服务接入可执行性评估，再实现验证有效期、配置哈希和确认发布。
4. 运行负责人提供 Run 和可查询的异步操作，B 接入启停及停止旧运行后启动新运行。
5. 接视频网关和带游标的事件订阅，处理去重、断流、重连和历史补拉。
6. 接事件证据、人工反馈、漏报，再完成复测与导出入口。

每一步都要有实际可验证的结果。整个智能体模块尚未完成，本轮完成的是它的草稿与版本基础。

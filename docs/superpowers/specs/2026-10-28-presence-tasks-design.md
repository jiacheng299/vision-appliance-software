# DeepSeek 模板选择与 YOLO 人员在岗监测

## 已确认目标

用户已确认使用 DeepSeek API，并批准：任务创建支持手动选择已发布模板或自然语言自动匹配；不足匹配时提示自定义创建模板，不执行未匹配业务。先交付真实 YOLO11n 人员在岗监测，默认区域内至少一人、连续无人 30 秒报警、置信度 0.5，可在任务中调整。

## 业务与数据

- 智能体管理继续拥有模板、已发布版本、模型引用和关联任务；不创建第二套模板目录。
- 每个发布模板固定绑定一个小模型及版本，修改模型生成新的模板版本，旧任务不自动升级。
- 模板可提供默认视频源；任务继承默认输入，没有默认输入时必须选择可访问的视频源。任务仍支持按需选择其他视频并重新校验区域。
- 默认在岗模板使用 YOLO11n COCO person 类；区域内人数小于最少人数且持续达到时长后生成真实缺岗事件；恢复人数后重置计时，重复报警受间隔控制。断流、停止、读帧失败不作为缺岗证据。
- 模型管理展示实际安装的 YOLO 模型、格式、版本、校验状态与模板绑定。未校验文件不进入执行目录。

## DeepSeek 边界

- 仅向 `https://api.deepseek.com/chat/completions` 发送自然语言需求、已发布模板说明及开放参数；不发送视频、凭据或本机路径。
- 默认 `deepseek-flash`，服务端 JSON 校验；匹配阈值 0.8，存在未覆盖需求或无有效候选时返回 no_match，引导用户创建模板，不自动生成可运行模板。
- 模型返回的模板 ID 必须属于本次候选且仍有效。用户选择、保存、验证、启动继续使用现有版本与幂等合同。
- Key 仅从本机受保护配置或环境变量读取；不进入 Git、浏览器响应或日志。缺 Key、限流、超时、无效响应明确报错，不冒充成功。

## 实现结构

- agent_templates/matching.py 与现有模板路由提供 match 和 matcher 状态；复用模板已发布版本。
- TemplateTaskCreatePage 重写为“选择方式 → 模板 → 参数/视频 → 验证启动”，保留草稿恢复、过期校验和防重复提交。
- models/yolo.py 负责可信 ONNX YOLO11n 的 CPU 推理与 person 后处理；安装脚本下载官方模型、生成 ONNX，并通过公开 API 注册模型和在岗模板。
- 独立 local_execution 模块实现 AgentServices 真实运行、事件、播放与统计，采用持久记录和有界后台执行；不借用 DemoServices 生成真实结果。
- 原多通道历史、摄像头预览、模拟隔离和固定版本保护保持可用。

## 验收

手动与 DeepSeek 两种选择均可得到同一人员在岗模板；不足匹配、缺 Key、API 异常、过期版本均可见。模型管理可见真实 YOLO11n。真实录像分别验证有人不报、无人超时报警、恢复重置与停止；摄像头断流不报缺岗。针对性红绿测试、全量回归、契约类型、生产构建及浏览器真实流程均需验证。

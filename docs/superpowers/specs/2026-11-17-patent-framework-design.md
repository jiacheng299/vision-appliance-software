# 专利框架落地：时效语义画像 · 有效观察 · 组合路由

本文件把《一种基于时效语义画像与有效观察校验的视频分析模型组合路由方法及系统》技术交底书的 M1–M9、S1–S14、式（1）（2）（3）与 F1–F5 映射到本仓库的实现，并明确哪些部分可实现、哪些降级、哪些暂不实现。

## 已确认目标

用户要求把现有网页与后端框架改造为交底书中的框架，不要求逐字一致；以该专利为核心支撑毕业设计。所有改动先 commit，未经允许不 push，需要可核对的验收文档。另一部分毕业内容是"多智能体强化学习应用于目标追踪"，本轮不实现，只预留接口。

## 现状与差距

现有系统已经具备交底书所需的"骨架"，但缺少方法本体：

| 交底书要素 | 现状 | 判定 |
| --- | --- | --- |
| F1 时效语义画像 | 无。只有 `source_identity` 摘要与连接诊断，不是场景属性 | 新增 |
| F2 任务需求图 | 无。单模型 + 硬编码规则链 | 新增 |
| F3 有效观察校验 | 有雏形：`presence.py` / `intrusion.py` 内嵌"只有成功解码帧才累计证据"；`safety_signals` 只做诊断 | 升级为显式判定 |
| F4 依赖式局部重路由 | 无 | 新增 |
| F5 版本化影子切换 | 有半套：Run 绑定 revision/source_snapshot，切源强阻断 | 补齐候选预热与原子切换 |

## 方案对比与决策

**方案 A：独立专利服务（新进程 + 独立库）**

与现有单体完全解耦，论文叙事干净。代价是模型/视频源/运行记录要跨进程同步，现有 `LocalAgentServices` 的单执行器文件锁、`BEGIN IMMEDIATE` 写事务、Run/Event 契约全部要复制一份，且要新增一套一致性协议。

**方案 B：在现有模块化单体上新增 `semantics` 与 `routing` 两个模块，执行器内嵌判定（推荐并已采用）**

复用现有 `RevisionConfig`/`RunDTO`/能力目录/持久层与迁移链，新增模块只拥有自己的表与纯逻辑；执行器按"影子优先"接入，先只写观察记录不改报警行为，验证后再切换。缺点是模块边界要靠约定守住。

**方案 C：重写执行器为路由驱动**

最接近交底书 S1–S14 的原貌，但要一次性替换 814 行的已验证执行器、显存/预算模型与全部回归用例，风险高于本轮收益。

选 B：它的风险最低、可用现有 445 项测试兜底，并且允许"先有证据、再谈路由"，避免在没有有效观察判据时就去写组合求解。

## 数据与判定

### 时效语义画像（F1 / M3 / 式(1)）

画像按 `(source_id, view_version)` 唯一。三层：

- 固有层：分辨率、镜头、安装位置、视场、码流、设备标识。来自设备表，不参与衰减。
- 动态层：光照、天气、季节外观、遮挡、背景材质、摄像机姿态。**每项必须带** 来源类型、来源帧时间戳、适用 ROI、观测时刻、置信度 `q_a`、衰减常数 `tau`、硬失效时刻 `T`、状态、版本。
- 运行层：当前模型组合、资源占用、路由版本、观察状态。

属性强度：

```
r_a(t) = q_a * exp(-(t - t_a) / tau_a) * I(t_a <= t < T_a)
```

纪律（与交底书与现有代码一致）：

1. `t < t_a` 视为时间戳异常，**拒绝该记录**，不参与任何判定。
2. `t >= T_a` 时强度置 0，状态改为 `expired`，**对外解释为"未知"，不得解释为相反事实**。
3. 来源冲突（语言推断 vs 画面实测）保留 `conflict` 态并降低强度，不静默取其一。

### 有效观察（F3 / M8）

观察记录五元组绑定：`摄像头 · 需求 · ROI · 帧窗口 · 执行路径`，并写入 `route_version`、`profile_version`、`model_version`。

五道门禁必须同时通过：

| 门禁 | 判据 |
| --- | --- |
| 帧时间 | 窗口非空；最大帧间隔 ≤ 阈值；实际帧率 ≥ 阈值 |
| ROI 覆盖 | ROI 可见比例 ≥ 阈值 |
| 画面质量 | 过曝比例 ≤ 阈值；模糊度 ≤ 阈值；遮挡比例 ≤ 阈值；最小可辨目标像素 ≥ 阈值 |
| 路径完整 | 各必需节点完成执行、输出协议可解析、时间与坐标映射有效 |
| 版本一致 | `route_version` / `profile_version` / `model_version` 与当前一致 |

三态结论：

- 任一门禁不通过 → `insufficient`（观察不足），附失效原因，**不得用于删除属性、撤销任务或证明事件不存在**。
- 五门禁通过且命中目标 → `detected`。
- 五门禁通过且为空集 → `not_detected`，**只在本次窗口与 ROI 内成立，不外推**。

检测节点的"协议有效空检测集"是合法输出，不因没有目标框而判为路径不完整。

## 不可实现或降级的部分（明确告知）

1. **设备报文推理服务**：本机没有真实设备平台，无法验证"仅推送已发生事件的报文"这一分支。实现上只保留其规则（报文缺失不得作为连续未检出证据），并在文档中标注未验收。
2. **独立低频多模态探针**：不接入外部探针服务。用本地图像统计（亮度/过曝/清晰度）与设备状态替代，作为"不依赖当前模型输出"的弱探针，并如实标注替代关系。
3. **M6 求解算法**：不引入 OR-Tools/整数规划。实现"硬约束过滤 + 预算约束贪心 + 小规模全枚举对照"，在文档中说明这是可解释的等价简化。
4. **过渡预算的显存维度**：单机 CPU 单模型，显存项退化为"CPU 毫秒 + 内存 + 解码句柄"。影子运行可真实执行（同进程加载第二个 ONNX 会话），但"显存迁移收益"无法量化，只量化"避免重解码/避免重载模型"的收益。
5. **式(2) 的 H(K) 依赖满足量**：需要离线标定表。本仓库只有 YOLO11n 一项真实能力，无法给出多模型分桶标定。实现为"种子能力表 + 显式未标定保守值"，**不允许把大模型自评写成准确率**；论文中必须声明该表为示例值。
6. **局部重路由的真实收益**：单模型场景下同一视频源共用解码，局部与全量重算的差别主要体现在不重建读取器与不重新初始化 ONNX 会话，可测；论文中的"显存迁移/轨迹中断"量化不可测，需注明。
7. **多智能体强化学习追踪**：本仓库不含训练循环与仿真环境。做法是抽出 `tracker` 策略接口（输入观测、输出关联动作），提供启发式默认实现，为后续接入 MARL 策略留出扩展点；真实 MARL 训练在独立工程完成，不在本仓库宣称已实现。

## 分阶段实施

- 阶段一（本轮）：`semantics` 模块——画像 + 式(1) + 画面指标 + 有效观察门禁 + 三态 + 持久化 + API + 测试。
- 阶段二：接入执行器影子模式（只写观察记录，不改报警），补齐 `RunDTO` 版本字段。
- 阶段三：`routing` 模块——需求图、能力表扩展、式(2) 求解、式(3) 滞回。
- 阶段四：漂移判定与局部重路由、影子运行与原子切换。
- 阶段五：前端页面改造（画像面板、观察记录、路由与切换视图）。
- 阶段六：MARL 追踪接口抽象与文档、验收汇总。

## 验收方式

每个阶段给出：纯逻辑单元测试（门禁、衰减、状态机、评分）、接口契约测试（字段与错误码）、现有回归用例全绿、生产构建通过、`docs/acceptance/` 下的验收记录。真实视频只用于验证"有效观察"是否真正区分三态，不用来宣称识别精度。
